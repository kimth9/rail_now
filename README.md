# kr-rail-timetable — 한국 철도 시각표 안드로이드 앱

> 상태: 데이터 파이프라인 구축 중(앱 미착수) · 스택: Kotlin/Compose + Room, Python 3(파서) · 최종 검증: 2026-08-25(서해선(전동) 반영 — 다운로드는 됐지만 파싱을 빠뜨렸던 마지막 코레일 전동열차 노선)

한국 전체 철도(고속철도 + 광역전철)의 시각표를 오프라인 DB로 담고, **Android 16 Live Update 알림**으로 열차 도착·출발을 추적하는 앱.

기존 웹 서비스(rail.blue 등)가 데이터는 풍부하지만 알림 기능이 없다는 점이 출발점이다. 이 프로젝트의 차별점은 데이터의 양이 아니라 **백그라운드에서 사용자를 깨우는 것**이다.

## 4. 동작 방식

### 4.1 2계층 데이터 모델

```
[베이스] 시각표   전 노선 · 오프라인 · 항상 존재
              ↓ 있으면 덮어씀
[오버레이] 실시간  수도권 광역전철 등 일부 구간만
```

시각표가 전국을 균일하게 덮으므로 화면 구조는 하나면 된다. 실시간 데이터가 있는 구간만 자연스럽게 정확해진다. 실시간이 없는 지역(부산·대구·대전·광주)은 "구멍"이 아니라 "오버레이 미적용" 상태다.

`fidelity` 값(REALTIME / SCHEDULED)으로 렌더러를 분기하고, **시각표 기반 구간에서는 실시간인 척하지 않는다** — 진행바 대신 단순 카운트다운, 텍스트에 "시각표 기준" 명시.

### 4.2 역 모델

```
station_groups (188)   ← 사용자 검색 단위       "수원"
      └── stops (195)  ← 노선별 승강장          "수원(1호선)", "수원(국철)"
              └── stop_times                   계통은 trips.line_name 태그
```

**노선까지만 나누고 계통은 나누지 않는다.** 구로역은 1호선 계통 5종(경인·경인급행·경부장항·서동탄-의정부·광명셔틀)이 지나가지만 승강장은 하나이므로 `구로(1호선)` 단일 항목이다. 계통은 목록 안에서 태그로만 구분한다.

(복수 노선 역사 개수는 노선 추가마다 빠르게 늘어나 여기 고정 수치로 유지하지 않는다 — 최신값은 `build_db.py` 실행 로그 참조.)

**동명이역 오병합 방지(merge_key).** 대구·대전·부산처럼 서로 무관한 운영기관을 섞기 시작하면서, 지역이 전혀 다른데 우연히 이름이 같은 역(충남 논산 `연산` vs 부산 `연산`, 서울/대구/부산 각각의 `교대`)이 실제로 나타났다. `station_groups.name_ko`/`stops.name_ko`는 **항상 깨끗한 역명 그대로**(지역 접두사 없음) 두고, 병합 여부만 각 파서가 `stops.csv`에 심는 `merge_key` 컬럼(빈 값이면 역명 자체가 키)으로 결정한다 — 같은 이름이라도 무관한 역이면 서로 다른 merge_key(`대구교대`, `논산연산` 등)를, 실제 환승역이면 두 파서가 같은 merge_key(`부산교대` 등)를 쓴다. 상세: `build_db.py`의 `add()`/`gid()`와 `meta.station_merge_key`. **노선을 추가할 때마다 빌드 후 "복수 노선 역사" 목록을 전수 점검해 확정하는 절차가 필수다.**

### 4.3 Live Update 알림 설계

Android 16 `Notification.ProgressStyle` 사용. 승격 조건은 `POST_PROMOTED_NOTIFICATIONS` 권한 + `setRequestPromotedOngoing(true)` + `setOngoing(true)` + `contentTitle`, 그리고 RemoteViews·그룹 summary·`setColorized(true)` 금지.

플랫폼 가이드가 Live Update를 **"진행 중 · 사용자가 시작한 · 시간에 민감한"** 활동으로 제한한다. 상시 표시되는 전광판은 여기에 어긋나므로 다음을 지킨다.

- 사용자가 "추적 시작"을 눌러야 알림이 뜬다
- 열차 도착·승차 시점에 종료하고 다음 열차로 자동 연장하지 않는다
- **Unpin** 액션 제공, `setDeleteIntent`로 사용자가 지운 알림은 재게시하지 않는다
- 상시 조회용은 알림이 아니라 앱 위젯으로 제공

매핑: 진행축 = 열차 현재 위치 → 사용자 역 / `Segment` = 역간 구간 / `Point` = 중간 정차역 / `setShortCriticalText` = 상태 칩("3분").

## 5. 스키마

```sql
stops(stop_id, display_name, name_ko, line, name_hanja, group_id)
station_groups(group_id, name_ko)
junctions(junction_id, name_ko)              -- 선로 분기점(승강장 아님)
trips(trip_id, train_no, line_name, formation, direction,
      service_id, origin, destination, next_train_no, source)
stop_times(trip_id, stop_seq, stop_id, arr_sec, dep_sec, stop_type)
calendar(service_id, mon, tue, wed, thu, fri, sat, sun)
meta(key, value)
```

GTFS 개념을 차용했다. 향후 GTFS 도구 생태계 활용이나 데이터 공개 시 유리하다.

**설계 결정 몇 가지:**

- **시각은 자정 기준 경과 초(정수).** `HH:MM` 문자열 대신 정수를 쓰면 심야 열차(25:17 → 91020)를 별도 변환 없이 정렬·비교할 수 있다. 86400 이상은 익일.
- **`stop_type`은 5종** — `origin` / `stop` / `pass` / `junction` / `destination`. `pass`는 급행 통과역의 통과 시각으로, "이 열차는 우리 역을 통과합니다" 안내에 쓸 수 있다.
- **`next_train_no`** — 1호선 원본의 연계열번. 종착 후 이어받는 열차번호로 차량 운용을 추적할 수 있다.
- 인덱스: `stop_times(stop_id, dep_sec)`, `stop_times(trip_id, stop_seq)`, `stops(group_id)`.

## 6. 원본 파일의 함정

파서를 수정할 때 반드시 알아야 할 것들. 개정판에서 다시 깨질 수 있는 지점이다.

### KTX 시각표

- **미정차 = `00:00:00`.** 빈칸이 아니다. 그런데 같은 파일에 `00:03`, `01:04` 같은 **실제 심야 도착 시각**도 있어, "0시대는 미정차"로 처리하면 막차가 날아간다. 정확히 `00:00:00`인 것만 걸러야 한다. 실제 시각이 정각 자정인 열차가 생기면 이 규칙이 깨진다.
- **역당 시각이 하나뿐.** 도착·출발 구분이 없어 `arr_sec`는 종착역에만 있다.
- 초 단위가 15초 눈금(`05:47:30`, `07:47:15`). 분 단위로 반올림하면 정보가 손실된다.

### 1호선 시각표

- **전치 구조.** 역이 행, 열차가 열. 역 하나가 2행(도착 / 출발)을 쓴다.
- **셀 패턴이 정차 유형을 결정한다.**

  | 패턴 | 의미 |
  |---|---|
  | 출발만 (첫 역) | 시발 |
  | 도착 + 출발 | 정차 |
  | **출발만 (중간역)** | **통과 — 통과 시각 기록** |
  | 도착만 (마지막) | 종착 |

- **역명이 3글자로 절삭됨.** `온양온`→온양온천, `가산디`→가산디지털단지, `평지제`→평택지제 등. 접두사 `1`은 서울 지하철 1호선 지하구간 표기(`1지청`→청량리, `1종로`→종로3가, `1동대`→동대문), `지하서`→서울. 매핑은 `parse_line1.py`의 `STATION_ALIAS`에 있고 `line1_stops.csv`로 검수 가능하다. **여기가 틀리면 환승 연결이 통째로 깨진다.**
- **`시흥연`은 역이 아니라 시흥연결선(분기점).** 도착시각이 한 번도 없다. `junctions` 테이블로 분리했다.
- `서울급행` 시트는 시각표가 아니라 조정안·현행 비교표다. 제외한다.

### 수인분당선 시각표

- **전치 구조는 1호선과 동일**하지만 헤더 행이 한 줄 더 있다(1행 "개정안" 제목 → 2~4행 시발역/종착역/열차번호 → 5행부터 역). `parse_line1.py`처럼 행 번호를 하드코딩하지 않고 "열차번호" 라벨을 찾아 헤더 위치를 잡는다.
- 시트 이름이 `평일상행`/`평일하행`/`휴일상행`/`휴일하행`으로 **구분자 없이 붙어 있다** — 1호선의 `그룹_요일_방향` 규칙과 다르다.
- **`신인천`/`신수원`은 절삭이 아니라 코레일 전산상 실제 역명 표기다.** 인천역·수원역은 경인선(1호선)측과 선로가 물리적으로 분리돼 있어, 수인분당선측을 시스템에서 별도 이름으로 관리한다(나무위키 "인천역" 문서 §2.2 확인). 원래 역명(`인천`/`수원`)으로 되돌려야 `build_db.py`의 노선 간 역사 그룹핑(station_groups)이 정상 작동한다 — 안 그러면 같은 역인데 별개 역사로 쪼개진다.
- 역명 복원은 감으로 하지 않고 나무위키 "수도권 전철 수인·분당선" 문서(역 목록·환승역·승하차 통계 표)로 전수 대조했다. 63개 역 전부 확정(미확인 `?` 항목 없음).

### 안산과천선(4호선 진접~오이도) 시각표

- 헤더·전치 구조는 수인분당선과 동일. 서울교통공사 구간(불암산~남태령)까지 포함해 **진접~오이도 전 51개 역이 한 파일에 다 들어있다** — 코레일이 직결운행 전체 시간표를 배포하기 때문.
- **`시흥기`는 정차역이 아니라 시흥기지(차량사업소)다.** 나무위키가 밝힌 정거장수(51개)와 원본 라벨 수(52개)를 대조해서 확인했다. `JUNCTIONS`로 분리.
- **`당고개`는 2024-10-31 `불암산`으로 개칭됐는데, 2026-08-22 갱신본에도 옛 이름이 그대로 남아있다.** `4동운`도 2009년 개칭 전 `동대문운동장`(현 동대문역사문화공원)의 흔적으로 보인다 — 코레일 내부 역명 마스터가 공식 개칭을 못 따라간 사례가 반복된다. 수인분당선의 `신인천`/`신수원`(전산상 정식 표기)과는 다른 종류의 함정이니 노선을 새로 추가할 때마다 나무위키의 "잦은 역명 분쟁"류 항목을 먼저 확인하는 게 안전하다.
- **`4`로 시작하는 라벨은 절삭이 아니라 호선 구분 접두사다** — 다른 노선에 같은 이름의 역이 있을 때만 붙는다(`4서울`=서울역, `4이촌`=이촌 등). 반대로 `미아4`처럼 끝에 붙는 `4`는 전혀 다른 규칙(`사거리`의 `사`를 숫자로 축약)이라 위치만 보고 일반화하면 안 된다.
- 역명을 복원할 때 기존 노선과 표기를 맞춰야 `station_groups` 병합이 된다 — 처음에 `서울역`으로 복원했다가 KTX/1호선의 `서울`과 안 묶여서 `서울`로 정정했다. `build_db.py` 실행 후 "복수 노선 역사" 출력에 예상한 역이 다 나오는지 확인하는 게 검증 방법이다.

### 경의중앙선 시각표

- 헤더는 1호선과 동일(3행: 시발역/종착역/열차번호, 4행부터 역) — 수인분당선·안산과천선의 "개정안" 제목행이 없다. 파서가 행 번호를 하드코딩하지 않고 "열차번호" 라벨을 찾아 헤더 위치를 동적으로 잡는 방식이라 그대로 대응됨.
- `연계열번` 행이 있다(1호선과 동일 패턴, 종착 후 이어받는 열차번호).
- **`1양정`/`1양원`은 절삭이 아니라 한국철도물류정보시스템의 내부 등록명이다.** 위키백과 "양정역(남양주)" 문서에 "한국철도물류정보시스템에는 1양정으로 등록되어 있다"고 명시돼 있다 — 수인분당선의 `신인천`/`신수원`과 같은 부류의 내부시스템 표기 함정이지만, 노선마다 걸리는 역과 표기 규칙이 다르므로 매번 확인이 필요하다.
- `도심`은 절삭처럼 보이지만 실제 역명이다(도심역, 덕소~팔당 사이) — 낯선 2글자 역명이라고 무조건 절삭으로 의심하면 안 된다.
- 이 파일은 문산~지평 구간만 포함한다. 임진강~문산 구간은 별도의 셔틀 운행(주중 2회·주말 4회)이라 이번 원본에 없다.

### 경의선 시각표

- 경의중앙선과 헤더·전치 구조·`연계열번` 패턴이 완전히 동일해 파서도 거의 그대로 복사됐다.
- **경의중앙선과는 다른 실제 운행 계통이다.** 경의중앙선은 가좌에서 용산선(용산·청량리 방면)으로 빠지고, 이 파일(경의선)은 가좌에서 신촌·서울역 방면으로 빠진다 — 물리적으로 다른 두 갈래가 가좌~문산 구간(19개 역)만 선로를 공유한다. `build_db.py` 실행 후 이 19개 역이 station_groups에서 "역명(경의중앙선),역명(경의선)"으로 정확히 묶이는 걸로 검증했다.
- 이 파일은 **도라산~서울** 구간까지 포함해 경의중앙선판(문산~지평)에는 없던 도라산·임진강·운천이 추가된다. `도라산`은 실제로 파싱해보니 전 트립에 걸쳐 정차 기록이 0건 — 나무위키의 "도라산~임진강 운행 중단" 서술과 일치한다(임진강~문산 구간의 희박한 셔틀편은 정차 기록이 있음).

### 경춘선 시각표

- 헤더·`연계열번` 구조는 경의중앙선과 동일.
- **`광운대시종착(평일)` 시트는 한 시트 안에 방향이 다른 두 블록이 좌우로 나란히 붙어있다** — A열은 상행(춘천→광운대), E열은 하행(광운대→춘천)이 각자의 "시발역/종착역/열차번호" 헤더와 역 목록을 따로 갖는다. 다른 노선 파서처럼 시트 하나 = 역 목록 하나로 가정하면 두 블록이 뒤섞여 잘못 파싱된다. 파서에 `(역명 열, 데이터 열 범위)`를 블록별로 지정해서 처리했다. 나무위키의 "춘천발 광운대행은 평일 2회"라는 서술과 파싱 결과(상행 2편·하행 2편)가 정확히 일치해 검증됨.
- `평내호`는 절삭이다 — 실제 역명은 `평내호평`(나무위키 승하차 순위표로 확정). 나머지 역명은 전부 절삭 없이 그대로.
- 휴일에는 `광운대시종착` 시트가 아예 없다(평일 한정 서비스라 시트 자체가 존재하지 않음 — 다른 노선처럼 "휴일 편수가 0"이 아니라 "휴일 시트가 없음"이라는 점에 유의).

### 경인급행(1호선 소속) — 새 노선이 아니라 개정판 교체

`RAW/`의 "경인선급행열차_20260526부터.xlsx"는 새 노선이 아니라 **1호선에 이미 포함된 경인급행 서비스의 최신 개정판**이다. 원본 `1호선_전동열차_*_20260228부터.xlsx`에도 `경인급행_평일_상/하`·`경인급행_휴일_상/하` 시트가 있었지만 날짜가 더 오래됐다(2.28 vs 5.26).

- `parse_line1.py`의 `SKIP_SHEETS`에 옛 경인급행 시트 4개를 추가해서 뺐다 — 안 빼면 같은 서비스가 신·구 두 버전으로 중복 집계된다.
- `parse_gyeongin_express.py`가 새 파일을 파싱하고, `build_db.py`는 이걸 **별도 노선이 아니라 `LINE_OF["LINE1"]`("1호선")로 등록**해서 기존 1호선 역(구로·영등포 등)과 stop_id를 공유시킨다. 역명 26개는 전부 기존 1호선 역명과 정확히 일치(절삭 없음).
- 교체 검증: 옛 경인급행 편수(평일 212 + 휴일 155 = 367)와 새 파일의 총 편수(367)가 정확히 일치 — 우연이 아니라 같은 서비스의 시간만 갱신된 개정판이라는 뜻이다. 교체 전후로 `stops`/`station_groups`/전체 `trips` 총량이 그대로인 것도 같은 이유.
- **다른 노선에서도 "새 파일 = 새 노선"이라고 무조건 가정하면 안 된다** — 코레일이 자주 개정되는 서비스(급행 등)만 별도로 자주 재배포하는 경우가 있다. 새 파일을 열어보고 역 목록이 기존 노선과 완전히 겹치면 이 패턴을 의심할 것.

### 경강선 시각표

- 헤더 구조는 다른 노선과 동일. `연계열번` 없음.
- **`신이매`/`신판교`는 절삭이 아니라 수인분당선의 이매·신분당선의 판교와 같은 이름이라 코레일 내부 시스템이 구분하려고 붙인 접두사다** — 수인분당선의 `신인천`/`신수원`과 정확히 같은 부류의 함정. 정식 역명(이매/판교)으로 되돌리면 이매가 수인분당선과 station_groups에서 정상 병합된다. `신` 접두사를 보면 일단 "동명역 구분 표기"부터 의심할 것 — 이번이 세 번째 사례(신인천/신수원, 당고개 유사 사례, 신이매/신판교)다.
- `세종릉`→`세종대왕릉`, `도예촌`→`신둔도예촌`, `경광주`→`경기광주`는 단순 3글자 절삭이 아니라 중간 음절을 건너뛴 압축 표기(예: `경`+`광주`, "기" 생략). 나무위키 역별 승하차 순위표로 전수 대조 완료.
- `부발`은 KTX 파일의 `중부내륙선` 시트와 겹쳐 station_groups에서 병합된다 — 중부내륙선 KTX가 판교~부발 구간에서 경강선과 선로를 공유하기 때문(나무위키에 명시).

### 동해선(전동, 부전~태화강) 시각표

- 헤더·`연계열번` 구조는 다른 노선과 동일. 시종착이 `망양`인 열차가 섞여 있는데, 정차역이 아니라 나무위키가 명시한 "차량기지 입출고용" 중간 시종착이다(경춘선의 광운대·안산과천선의 시흥기지 사례와 같은 패턴).
- 역명 대부분 단순 3글자 절삭(`오시리`→오시리아, `신해운`→신해운대, `부산원`→부산원동, `거제해`→거제해맞이). `부교대`→`교대`만 예외인데, 부산 도시철도 3호선에도 같은 이름의 역이 있어 붙는 구분 접두사로 추정된다(나무위키 역별 승하차 순위표에서 실제 표기가 `교대`로 확정).
- **"동해선"이라는 이름이 이 파일·KTX 파일·일반열차 파일에 각각 다른 실체로 존재한다** — 계획 단계에서 미리 파악해둔 함정이 실제로 발생했다. `build_db.py`에서 `line_name`을 `동해선(전동)`으로 구분해서 등록했다. 결과적으로 부전·태화강·남창·기장·신해운대·센텀 6개 역이 KTX(국철)의 동해선 시트들과 station_groups에서 정상 병합됐다 — KTX-이음이 같은 구간에서 선로를 공유하기 때문. 나중에 일반열차 파일의 `동해선` 시트를 반영할 때도 반드시 `동해선(일반)`처럼 구분자를 붙여야 한다.

### 대경선(구미~경산) 시각표

- 헤더·`연계열번` 구조는 다른 노선과 동일. 역명 14개 전부 절삭 없이 실명(이 노선은 이름이 아니라 **구성**이 함정이었다).
- **원본 라벨이 14개인데 나무위키의 공식 역 수는 8개다.** 나머지 6개(가천·고모·지천·신동·연화·약목)는 실재하는 역이지만 대경선 열차가 **통과만** 한다(무궁화호 등 일반열차는 일부 정차) — 나무위키에 "코레일 시간표 파일에는 저 6개 역의 통과 시간도 표시되어 있다"고 명시돼 있다. 시흥기지(비역)나 도라산(운행 중단)과는 다른 패턴이라 JUNCTIONS로 빼거나 제외하지 않고 일반 역으로 등록 — 기존 stop_type 분류 로직이 도착·출발 중 하나만 있으면 자동으로 `pass`로 처리하므로 그대로 맞는다.
- 서대구·동대구·경산이 KTX(국철) 시트와 station_groups에서 병합된다 — 이 역들에 KTX도 정차하기 때문. 대구·구미·사곡·북삼·왜관은 KTX가 서지 않아 단독 역으로 남는다.

### 일산선(3호선 오금~대화) 시각표 — 전동열차 노선 중 마지막

- 안산과천선과 같은 패턴: 서울교통공사 구간(지축~오금)까지 포함해 **오금~대화 전 44개 역이 한 파일에 다 들어있다**(코레일이 직결운행 전체 시간표를 배포).
- **`3`으로 시작하거나 끝나는 라벨은 절삭이 아니라 3호선 구분 표기다** — 안산과천선의 `4` 접두사와 같은 부류(예: `3수서`=수서, `3충무`=충무로). 이번 노선에서 확인된 것만 8건(`3수서·3도곡·3옥수·3충무·3을지·3종로·3대곡·금호3`) — `3`이 접두사로도 접미사로도 붙을 수 있어 위치만 보고 패턴을 일반화하면 안 된다(경춘선의 `미아4`에서 이미 한 번 겪은 교훈).
- `동대입`은 절삭이 아니라 정식 역명 자체가 `동대입구`다(`동대문입구`가 아님) — 나무위키로 대조하지 않았으면 잘못 복원했을 뻔했다.
- 검증이 특히 잘 맞아떨어졌다: `build_db.py` 결과 수서(국철·수인분당선·일산선 3-way)·종로3가(1호선)·도곡(수인분당선)·충무로(안산과천선)·옥수(경의중앙선)·대곡(경의중앙선·경의선·일산선 3-way)·교대(동해선(전동)) 전부 예상대로 병합됨 — 특히 `교대`는 동해선의 `부교대`가 왜 그런 접두사를 썼는지(3호선 교대와 동명이라서)를 이 노선을 반영하며 최종 확인했다.
- 이 원본만 게시일이 2025-08-06(기준일 2022.8.1.부터)로 다른 전동열차 노선들(2026년 초중반 갱신본)보다 오래됐다 — 코레일 다운로드 게시판에서 확인 가능한 최신본이 이것뿐이었다.

### ITX-청춘(용산~춘천) 시각표

- 여객열차(전동차 아님)라 계획 문서에서 순서상 가장 마지막으로 미뤄뒀다. 헤더·`연계열번` 구조는 다른 노선과 동일.
- 경의중앙선(용산~청량리, 경원선 구간)과 경춘선(청량리~춘천)을 그대로 이어 달리는 열차라 **역명 31개가 전부 이미 그 두 노선에서 나무위키로 검증된 것들**이었다 — 새로 조사할 역이 없었다.
- `build_db.py` 결과 31개 역 전부 기존 경춘선·경의중앙선 station_groups로 병합되고 **새 그룹은 0개** — 노선 간 역명 표기가 완벽히 일관됐다는 뜻. 이것으로 계획 문서(`~/.claude/plans/ethereal-herding-crown.md`)의 전동열차+ITX-청춘 항목이 전부 끝났다.

### 서해선(전동, 대곡~일산 직결) 시각표

- 헤더·`연계열번` 구조는 경의선·경의중앙선과 완전히 동일한 그룹 A 계열이라 `parse_gyeongui.py`를 거의 그대로 재사용했다.
- **원본에 문산 방면(탄현~판문) 12개 역이 빈 꼬리 행으로 붙어있었다.** 시각이 전부 비어있는 걸로 보아 경의선 파일을 복사해서 만들다 지우지 않고 남긴 흔적으로 추정 — 시각 데이터가 하나도 없는 역은 애초에 `stops`에 등록하지 않도록 필터를 추가했다(경의선 파서처럼 "미사용 역"으로 남겨두는 대신 원천 제외 — 문산 계열 역은 이미 경의선 파서가 등록해 뒀으므로 중복도 아니다).
- **역명 21개 중 9개가 "신" 접두사 패턴.** 기존에 확인된 신인천/신수원/신이매/신판교와 같은 부류(코레일이 다른 노선의 동명역과 구분하려고 붙이는 내부 표기)로, `신초지`→초지·`신신현`→신현·`신신천`→신천·`신소사`→소사가 그 예다. 이 중 `신초지`·`신소사`는 각각 수인분당선/안산과천선의 `초지`, 1호선(경인선)의 `소사`와 물리적으로 같은 역이라 station_groups 병합으로 실제 검증됨. 나머지는 단순 3글자 절삭(`시흥능`→시흥능곡, `시흥청`→시흥시청, `시흥대`→시흥대야, `부천종`→부천종합운동장).
- **`신김포`→김포공항 하나만 패턴이 이례적이다.** "신"+2자 실명(신현·신신천 등)도, 단순 3글자 절삭도 아니고 "신"+절삭이 겹친 형태 — 나무위키 "서해선/역 목록"에서 원종↔능곡 사이에 오는 역이 김포공항 하나뿐이라는 위치 대조로 확정했다(현재 DB에 5호선·9호선·공항철도가 없어 station_groups 병합으로는 검증 못 함 — 추후 그 노선들을 반영하면 재확인 가치 있음).
- **노선명 충돌** — 일반열차 파일에도 서화성~홍성 구간(ITX-마음)을 도는 별개의 "서해선"이 이미 등록돼 있어(계획 단계에서 예상했던 함정), 동해선과 같은 방식으로 `line_name`을 `서해선(전동)`으로 구분했다.
- 검증: 소사(1호선)·초지(수인분당선·안산과천선)·대곡/능곡/곡산/백마/풍산/일산(경의중앙선·경의선)이 station_groups에서 전부 예상대로 병합됨. 세션 초반에 이미 다운로드해뒀지만 파싱을 빠뜨렸던 마지막 코레일 전동열차 노선이었다.

### 일반열차(무궁화·ITX-새마을·ITX-마음) 시각표 — 지금까지와 다른 두 가지 축의 함정

- **레이아웃이 KTX와도 전동열차 계열과도 다르다.** 역=행/열차=열의 전치 구조라는 점은 전동열차 계열과 같지만, 역당 시각이 1개뿐이라는 점은 KTX와 같다(KTX는 반대로 열차=행/역=열). 게다가 실제 데이터 열 뒤에 열 라벨의 한자·영문 버전이 별도 열로 붙어있어(`열차번호`→`列車番號`→`Train NO.`), 단순히 "빈 칸까지" 읽으면 이 라벨 열을 열차로 오인한다 — 열차번호는 항상 숫자라는 성질로 필터링해서 해결.
- 시트 하나에 하행/상행 블록이 세로로 쌓여 있고(목포보성선·경전선·서해선은 하행만 있음), 블록 경계도 행 번호 고정이 아니라 "OO선 하행/상행" 제목 → 열차번호 → 비고 순서로 마커를 찾아 동적으로 판별해야 했다.
- **원본 자체에 데이터 이상치가 있었다.** 호남선 열차 1491/1492는 이미 종착한 역 바로 다음 행에 이전 열차의 시각이 찌꺼기로 남아있었고, 장항선 1246은 "종착역=홍성"이라는 라벨 자체가 틀려 있었다(실제로는 홍성을 지나 평택까지 정상 운행). 종착역 라벨을 기준으로 뒤 데이터를 잘라내는 방식을 시도했지만 후자 사례를 오히려 망가뜨려서 되돌리고, 자정 넘김 보정 임계값(6시간 이상만 다음날로 판정)으로 24시간짜리 가짜 소요시간만 막는 선에서 타협했다 — 경고 로그에 남아있는 3건은 사람이 원본을 다시 봐야 하는 항목.
- 노선명 충돌(경부선·호남선·전라선·경전선·중앙선이 KTX 시트와 겹침, 동해선은 동해선(전동)과도 겹침)을 막으려고 **모든 15개 노선명에 `(일반)` 접미사**를 붙였다. stops는 KTX와 같은 `LINE_OF["KTX"]`("국철")로 묶어서 역은 공유하되 trips.line_name만 구분.
- 검증: 안양·오산·평택·천안·아산 등 1호선 역, 구미·약목·왜관·신동 등 대경선 역과 station_groups에서 정확히 병합됨 — 특히 약목·신동은 대경선 나무위키 문서에 "무궁화호가 일부 정차"라고 적혀 있던 걸 이번에 실증했다.

### 관광열차(동해산타·V-트레인·남도해양·서해금빛·정선아리랑) 시각표 — 가장 비정형이었던 파일

- 지금까지 본 어떤 노선과도 다른 레이아웃이다. 한 시트 안에 서비스 6개(왕복 편성 14개)가 손으로 짜 맞춘 듯한 작은 표로 흩어져 있고, 행/열 번호 규칙이 전혀 없다.
- **"역명" 셀을 전부 찾는 마커 스캔으로 해결했다** — 역명 헤더 바로 위 행이 그 편성의 제목(`#2502(강릉→영주)`), 그보다 위에서 가장 가까운 "OO열차(요일)" 텍스트가 서비스명이라는 규칙만으로 14개 편성 전부를 좌표 하드코딩 없이 찾아냈다.
- **블록 사이에 빈 행이 없는 경우가 있었다** — 백두대간협곡열차(V-트레인)의 연계편(#2511→#2512→#2514)이 같은 열에서 바로 이어 붙어 있어서, "빈 칸을 만나면 역 목록 끝"이라는 종료 조건만 쓰면 다음 편성의 제목·헤더까지 역명으로 잘못 읽어버렸다. 다음 블록의 `#`제목이나 `역명` 헤더를 만나도 멈추도록 종료 조건을 추가해서 해결.
- 시각 값이 `datetime.time` 객체와 `"08:30"` 형태의 문자열이 섞여 있어 `to_sec()`이 둘 다 처리하게 만들었다.
- 운행요일이 "목~일"(연속 구간), "목~월"(주 경계를 넘는 구간), "2·7일 장날, 토~일"(날짜 기반 임시 증편이 섞인 구간)까지 있다. 요일 구간(`~`)만 calendar에 반영하고 날짜 기반 부분은 반영하지 않았다 — 필요해지면 calendar_dates류 예외 테이블로 확장.
- 이 노선들은 KTX·일반열차와 같은 선로를 달리므로 stops를 "국철"로 등록 — 역 58개 전부 기존 국철 역과 병합되고 새 역은 0개.

### 서울교통공사 2·5·6·7·8·9호선 시각표 — 노선마다 레이아웃이 다르다

- **3호선은 반영하지 않았다** — RAW의 "서울3호선" 파일을 실제 열차 도착시각으로 대조해보니 이미 반영된 `일산선`(코레일 배포본)과 완전히 동일한 실제 운행 데이터였다(대화역 05:16 출발 열차가 양쪽 파일에서 정확히 일치). 새 데이터가 아니므로 스킵.
- 2호선은 순환선이라 direction이 상행/하행이 아니라 outer(외선)/내선(inner). 평일본(2026)은 명시적 "도착/출발" 라벨 열 + datetime 값, 휴일본(2022, 4년+ 오래됨)은 라벨 없는 암묵적 2행1조 + 텍스트 값 — 완전히 다른 두 레이아웃이라 한 파서(`parse_seoul2.py`)에 자동 감지 로직을 넣었다.
- 5·6·8호선은 서로 같은 "명시적 라벨" 구조. 6호선 평일 원본은 역명 글자 사이에 공백이 끼어있고(`화 랑 대`), 휴일 원본에는 오타(`개농`→개롱)·구역명(`동대문운동장`→동대문역사문화공원)·분리표기(`응암(상)`/`응암(하)`→응암)가 남아있어 정규화가 필요했다.
- 8호선은 RAW 후보가 3개(2023/2024/2025)였는데, 2025-06-02 최신본이 평일·휴일을 한 파일에 다 포함하고 있어 그것 하나만 쓰고 나머지 둘은 버렸다.
- 7호선은 5호선과 같은 구조이나 평일(2026)·휴일(2022) 원본의 헤더 라벨 자체가 다르다(출발역/도착역 vs 시발역/종착역). 역명도 절삭·개명이 섞여있었다 — `가산디지털`→가산디지털단지, `총신대입구`/`이수`→총신대입구(이수)(안산과천선과 표기 통일, 실제 환승역), `뚝섬유원지`/`자양`→자양(뚝섬한강공원)(2024.2월 개명).
- 9호선은 No./역명/구분(도착·출발) 3열 헤더 + 일반열차·급행열차 시트 분리. 평일/휴일 기준일이 유일하게 일치(2024.3.30).
- **동명이역 오병합 6건 추가 발견**(송정: 부산 동해선 vs 5호선, 월드컵경기장: 대전1호선 vs 6호선, 신흥: 대전1호선 vs 8호선, 증산: 부산2호선 vs 6호선, 종합운동장: 부산3호선 vs 2·9호선, 상동: 국철 경부선(밀양) vs 7호선(부천)) — 전부 `merge_key`로 분리(§4.2 참조).

## 7. 알려진 제약·주의

- **공휴일 미반영.** `휴일` 다이어가 토·일에만 자동 적용된다. 설날·추석·광복절 등 공휴일에도 휴일 다이어로 운행하므로 `calendar_dates` 예외 테이블이 필요하다. 공휴일 목록은 공공데이터포털 특일 정보 API로 받는 편이 대체공휴일까지 커버되어 안전하다.
- **토요일 다이어.** 대구·부산 도시철도는 평일/토요일/휴일 3종이 실제로 별도 존재함을 확인·반영했다. 서울교통공사·국철 계열은 평일/휴일 2종만 확보 — 노선별로 재확인 전까지는 토요일 = 휴일로 가정한다.
- **서울교통공사 평일/휴일판 기준일 격차.** 노선마다 최신 확보본의 시차가 크게 다르다 — 2·7호선은 평일 2026.8.21 vs 휴일 2022.4/6(4년+ 차이, 가장 심각), 5·6호선은 10~14개월, 9호선만 기준일 일치(2024.3.30), 8호선은 2025.6.2 단일본이라 문제 없음. 재확보 전까지 이 상태로 진행하기로 확정(사용자 결정).
- **임시열차 없음.** 명절 증편, 주말 임시열차, 공사 운휴가 반영되지 않는다. 앱이 가장 많이 쓰일 명절에 정작 임시열차가 안 보이는 문제가 있다.
- **지연 미반영.** 정적 시각표만으로 진행바를 그리면 20분 지연된 열차도 "곧 도착"으로 표시된다. 실시간 오버레이가 없는 구간에서는 진행바를 쓰지 않는다.
- **갱신 채널 미구축.** 다이어 개정 시 앱 업데이트 없이 시각표를 교체할 수단이 없다. 원격에 번들을 두고 `meta`의 버전만 확인해 받아오는 구조가 필요하다(정적 호스팅으로 충분).
- **DB 크기 100MB 초과(2026-08-26, 101.3MB).** 코레일 계열(18개)+대구·대전·부산·서울교통공사(15개 노선)까지 반영한 시점. 인천1·공항철도·크롤링 8곳·추정 2곳·사진 1곳·신분당선을 더 반영하면 계속 커진다 — 압축·분할 배포 판단이 필요하다(사용자 확인 대기, `todo.md` 참조).
- **일반열차 원본 데이터 이상치.** 호남선 1491/1492, 장항선 1246 등 소수 열차에서 원본 스프레드시트 자체의 시각·라벨 오류가 확인됐다(§6 참조). 자정 넘김 오판만 막아뒀을 뿐 근본 수정은 아니라, 해당 열차들의 후반부 정차 시각은 신뢰도가 낮다.
- **승강장 계층 없음.** 서울역 지하 1호선 ↔ 지상 KTX 도보 이동시간 같은 환승 정보가 없다. 필요해지면 `station_groups`에 `transfer_min`을 얹는다.
- **파서 회귀 테스트 없음.** 개정판마다 레이아웃이 바뀌면 조용히 틀린 데이터가 생성된다. §8의 검증 항목을 스크립트화해 파이프라인에 넣어야 한다.

## 8. 검증 항목

개정판을 넣을 때마다 확인한다. 파서가 깨졌는지 즉시 드러난다.

- 역 순서가 단조 증가하는가 (시각 역행 = 파싱 오류)
- 역간 소요시간이 상식 범위인가 (현재: KTX 5~72.5분, 1호선 0.5~7.5분)
- 첫차·막차 시각이 이전 버전 대비 크게 튀지 않았는가
- 열차 편수가 이전 버전 대비 급변하지 않았는가
- 역 집합이 이전 버전과 일치하는가 (신설역 외 차집합 0)
- 절삭 역명 매핑에 미확인(`?`) 항목이 남아있지 않은가
- **(2026-08-26 추가) `build_db.py` 실행 로그의 "복수 노선 역사" 목록을 전수 점검** — 서로 다른 운영기관을 섞을 때 특히 중요. 새로 등장한 항목마다 실제 환승역인지(자연스러운 병합) 아니면 무관한 지역의 동명역인지(`merge_key`로 분리 필요) 확인한다

rail.blue와의 대조도 유효하다. 열차 1번(서울 05:13 출발)이 부산 도착 07:52(rail.blue) vs 07:50(현재 파일)로 다른데, 이는 오류가 아니라 다이어 개정 결과로 판단했다.
