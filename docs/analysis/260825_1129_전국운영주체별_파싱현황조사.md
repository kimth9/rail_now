## 핵심 결론

현재 파이프라인(`output/kr_rail_timetable.sqlite`)은 **한국철도공사(코레일)가 직접 운영하거나, 코레일이 시각표를 대신 배포하는 노선**만 커버한다. 전국 도시철도/광역철도 노선의 대다수(서울교통공사, 부산교통공사, 대구교통공사, 대전교통공사, 광주교통공사, 인천교통공사 및 각종 민자·경전철 사업자 운영분)는 코레일 다운로드 게시판에 없으므로 애초에 이 프로젝트의 데이터 소스 범위 밖이었다.

다만 조사 중 사용자가 대구·대전 4개 파일을 이미 RAW에 직접 확보해 두었음을 확인 — 아래 "신규 확보" 항목 참조.

## 신규 발견 — 대구·대전 파일 (사용자가 세션 중 RAW에 직접 추가)

세션 중 사용자가 아래 4개 파일을 `RAW/`에 직접 배치:

- `대구 열차별 운행시각표(1호선) - 게시용.xlsx`
- `대구 열차별 운행시각표(2호선) - 게시용.xlsx`
- `대구 열차별 운행시각표(3호선) - 게시용.xlsx`
- `대전 열차운행시각표(2026.3.30.).xlsx`

openpyxl로 구조를 확인한 결과:

- **대구 1/2/3호선** — 시트 6개(`N호선(평일/토요/휴일)상행/하행`), 역=2행 1조(역명행+시각행) 전치 구조로 기존 그룹 A(1호선 등)와 유사하나, 상단 헤더가 3행(시발역/종착역/열차번호)이 아니라 2행(열차번호만, 예: `51,53,...` + `1001,1003,...`)뿐이라 `parse_line1.py`를 그대로 재사용할 수 없음 — 신규 파서 필요.
- **대전 1호선** — 시트 4개(`판암행_평일/휴일`, `반석행_평일/휴일`), 출발역 기준 분단위 그리드(역명 셀 하나 아래 여러 시각이 행마다 나열, KTX·1호선 계열과 전혀 다른 "역별 배차표" 레이아웃) — 이 역시 신규 파서 필요.

두 곳 모두 **코레일이 아닌 지방 교통공사 운영**이므로 `build_db.py`에 등록하더라도 기존 "국철" 계열과 역명은 공유하지 않고 완전히 별도 노선망으로 취급해야 한다(대구 도시철도 1/2/3호선 ↔ 대경선은 대구역·동대구역·서대구역에서만 물리적으로 만남, 대전 1호선은 코레일 노선과 물리적 환승역 없음 — 판암·반석 모두 일반철도와 접점 없음).
